# Stage B2.3 思考预算小样本诊断设计

冻结日期：2026-10-13。此目录是新实验，保留原 Stage B2.3 输入、输出、报告不变。

## 样本

来源为 B0.2 冻结 Primary test 的全部 2063 条，内容从 B1 union_manifest 读取。核对两个来源的 test row_id 集合完全一致。真实查询路径长度 h1–h5 分别有 712、505、422、282、142 条。

本诊断按每 hop 抽 2 题，共 10 题。固定 seed 为 20261013。对每个 hop 内的候选按以下字符串的 SHA256 值排序，取前两条；极端相同哈希时按整数 row_id 排序：

`stage-b2-3-budget-pilot|20261013|<computed_hop>|<row_id>`

抽样没有读取已有生成答案，也没有按正确性、解析成功、生成长度或截断状态筛选。文件中 gold 只用于评估，不进入模型输入。

## 预算比较

计划比较 max_new_tokens=8192、16384、32768。三档复用相同 10 个输入、相同 prompt、相同 thinking 设置与采样参数。生成 seed 应另外记录，不能把样本选择 seed 自动解释为原 B2.3 生成 seed。硬件、软件版本、每档 batch、显存和实际速度记录在运行产物。

预算包含思考与最终答案的全部新生成 token。只改变预算有利于配对观察；由于采样与批形状可改变生成轨迹，不应假定较大预算的输出必然是较小预算输出的严格续写。OOM 或运行失败应保留诊断记录，不能以失败样本替换样本名单。

优先观察每题实际新 token 数、正常结束、思考段是否关闭、最终答案能否解析、最终正确性、墙钟时间和显存。原生完整生成与任何强制中断后补答应分开记录。

## 结论范围

每 hop 等量抽样会相对自然 test 分布过采样 h4/h5，因此这是等 hop 的诊断集合，不能代表总体分布。10 题可用于判断流程能否运行、预算是否改善完成、显存和吞吐；准确率变化仅作个案线索，不能形成可靠总体推断，也不能据此选出最优预算。更大样本实验应在本轮真实耗时和完成率基础上再设计。

sample_manifest.json 保存输入内容、来源文件 SHA256、抽样算法及每题内容 SHA256。每题内容 hash 覆盖 row_id、computed_hop、canonical_relation、story、question 的 UTF-8 canonical JSON；详情见 JSON 中 content_hash_definition。
